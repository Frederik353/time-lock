The Math
TL·2
how it works

A time lock encrypts a short secret so that getting it back takes a fixed amount of waiting. It’s meant to stop you acting on a whim. Someone determined to get in can still get in.

Locking picks two random ~1024-bit primes (Miller-Rabin tested) and multiplies them into a ~2048-bit modulus, along with a random base g:

N = p · q   (p, q ≈ 1024-bit primes)

The answer is a single number, reached by squaring g a huge number of times, t of them:

key = g^(2ᵗ) mod N

Locking knows the factors, so it knows φ(N) = (p−1)(q−1) and takes Euler's shortcut: shrink the exponent first, then one modular exponentiation lands on the key instantly.

e = 2ᵗ mod φ(N)
key = gᵉ mod N

Then it throws p, q and φ(N) away. Unlocking is left with only N, g and t. With no factors there is no shortcut. The only known route to the key is to actually walk the t squarings, one after another:

x₀ = g
xᵢ = xᵢ₋₁² mod N
key = xₜ

Each square needs the one before it, so the work is inherently sequential: more cores, a GPU, splitting it up, none of it helps. That unavoidable chain is the delay. (The Rivest-Shamir-Wagner time-lock puzzle, 1996.)

The grid is that value, live. N is about 2048 bits = 256 bytes, and the grid is 16×16 = 256 cells, one cell per byte of x, the number currently being squared. Each cell's brightness tracks its byte (0 dark → 255 bright); bytes near the top of the range tint orange. Squaring mod N is an avalanche: nudge the input and every bit of the output scrambles, so the whole grid reshuffles on every frame. It refreshes once per batch of a few thousand squarings, so between two frames the number has already jumped thousands of steps. It isn't decoration played over the computation; it is the computation.

How big is t? When you lock, it measures how many squarings per second this machine manages and sets t = rate × seconds. The wait is calibrated to the device you lock on, and it is honest about hardware: unlock on something much faster and it finishes sooner.

Thermal note. The squarings cannot be split across cores, so unlocking pins a single core at full tilt. On a phone or a thin laptop that core heats up and the chip throttles, which lowers the squaring rate, so a long unlock can run slower than you picked. A well-cooled machine holds its clock and stays on schedule.

The secret itself is encrypted with AES-GCM under key = SHA-256(xₜ). The reset/pause choice is mixed into GCM's authenticated data, so flipping that flag in the token makes the final decryption fail. You change the behaviour by rewriting this page, not by editing the token.

Reset wipes all progress if you leave the tab, so an impulse costs you the whole wait again; pause only stops the clock. Either way the screen is kept awake while it grinds.

Friction, not a vault. The token isn't a secret, and faster hardware or code could solve it quicker. Everything runs in your browser; nothing is ever sent anywhere.
